# MT400 Optional 58A Implementation Plan

> **For Codex:** Implement with TDD and validate the exact candidate before independent review.

**Goal:** Make MT400 field 58A optional in the governed OUTWARD SSI Resolve workbench while preserving a user-supplied value as unvalidated transaction context.

**Architecture:** Keep the governed OAS/page-parameter policy as the single source of truth. The shared page-definition and submission adapters will consume that policy; no MT400-specific UI template or CSS will be introduced.

**Tech Stack:** Angular, NestJS, TypeScript, Jest/Nx, governed JSON parameters.

---

## Task 1: Establish the failing contract

- Change the MT400 OAS policy and page-definition test expectations from required to optional.
- Add or confirm submission coverage showing MT400 can omit 58A and can preserve it when supplied.
- Run focused tests and retain the expected Red result before production changes.

## Task 2: Apply the minimum governed change

- Change only `MT400_BENEFICIARY_TRANSACTION_INPUT` to `required: false`.
- Do not change MT742, MT754, or any message outside the approved MT347 Index scope.
- Run the focused tests to Green and refactor only if duplication or dead code is proven.

## Task 3: Validate the candidate

- Run affected tests, lint/type checks, build, and `npm run verify`.
- UI-test MT400 direct canonical route both without 58A and with a user-selected 58A.
- Confirm omission does not fabricate 58A and a supplied value is marked transaction-context provided/unvalidated.

## Task 4: Controlled review

- Commit the exact candidate.
- Obtain Independent Checker and QA review against that exact Git commit and logical dataset snapshot.
- Stop after approval and report the result; do not merge without a separate instruction.

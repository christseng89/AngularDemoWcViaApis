# 源文件到知识映射

本页将每个已分析的源码/文档文件，映射到由其产出的业务规则笔记。当某个源文件发生变更时可用本页查找：该文件下列出的每一条规则都是需要重新核实是否过时的候选对象（本知识库沿用了代码仓库自身"保持测试与文档同步"的既定规则）。

**快照基准：** 2026-08-22／26 的早期资料无法锁定 commit；2026-08-30 增量同步已锚定 commit `3917866`。本页既有表格保留历史来源映射，本轮新增来源与影响范围见 [[Freshness-Update-Log-2026-08-30]]。

**覆盖范围：** 在 20 个萃取分组、约 180 个已分析文件中，共有 94 个不同的源码/文档文件被至少一条业务规则引用为证据。

**2026-08-26 增量同步：** 新增 5 个源文件（`domain/expiryEligibility.ts`、`domain/reopenRestoration.ts`、`domain/autoCloseGracePeriod.ts`、`domain/domesticCalendar.ts`、`src/app/transaction-builder/domestic-calendar.ts`），并为既有的 `balanceService.ts`、`statusTransition.ts`、`errors.ts`、`balance-component.model.ts`、`builder-fields.ts`、`submit-rules.ts`、`function-strategy.ts`、`document-arrival-hints.service.ts`、`maker-panel.component.ts`、`checker-panel.component.ts` 追加了本次新增规则的链接。详见 [[Freshness-Update-Log-2026-08-26]]。

**2026-08-30 增量同步：** 复核 `balanceService.ts` 及其 service collaborators、Transaction Index UI、Business Case Runner lifecycle、两份 OAS 与 2,466 项测试基准。新增 [[BalanceService Facade Architecture]] 与 [[Transaction Index Selection Contract]] 两个聚合知识节点。

**2026-08-31 增量同步：** 复核 `InquireDeletePendingComponent` 的 standalone dependency 边界；移除模板未使用的 `TbIconComponent` 后，确认无 API contract 变化，两份 OAS 保持不变。详见 [[InquireDeletePendingComponent]]。

**2026-09-03 增量同步：** A2／B2 改为修改前后完整上限差额，依币别 `ROUND_HALF_UP`；新 Tolerance 在 Checker Release 后才生效。`AMEND_EXPIRY_DATE` 不接受 Tolerance；ACTIVE 为纯日期修改，EXPIRED 则在同一笔 PENDING Amendment 呈现 RELEASED EXPIRE 的恢复分录，Release 后才恢复余额。CANCELLED／REJECTED retry 不遮蔽恢复依据。Runner 增加同一合约四种 Amount × Tolerance 组合。详见 [[Freshness-Update-Log-2026-09-03]]、[[TOLERANCE-RULE-015]]、[[MOVEMENT-RULE-066]] 与 [[MOVEMENT-RULE-068]]。

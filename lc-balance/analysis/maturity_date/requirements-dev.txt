# format-nongpl (not the plain "format" extra) pulls in rfc3339-validator
# (required for the date-time format checker used by validate_semantics.py)
# plus fqdn/idna/isoduration/jsonpointer/uri-template/webcolors, while using
# rfc3986-validator + rfc3987-syntax instead of the GPL-licensed rfc3987 for
# URI formats. This spec does not use format: uri/email/hostname, so the
# choice between the two extras has no functional effect here -- nongpl is
# used purely to keep the dependency tree license-clean by default.
# Round 7 found that jsonschema>=4.0 alone (no extra) does NOT guarantee
# format: date-time is actually validated: jsonschema imports
# rfc3339_validator inside a `with suppress(ImportError)` block, so on a
# machine where it's missing, the "date-time" checker is silently never
# registered and invalid timestamps pass through with no error at all.
# validate_semantics.py's startup fail-fast check (round 8) turns that
# silent gap into an immediate RuntimeError instead of a false-green CI run.
#
# Round 10: the floor is raised to >=4.18 (with a <5 ceiling) because
# validate_semantics.py's round-9/10 RefResolver migration uses the
# registry=/Registry-based referencing integration that jsonschema first
# shipped in 4.18.0 -- jsonschema>=4.0 alone would still satisfy this line
# while installing an early 4.x release that predates the public
# `registry=` constructor argument the script now depends on, which would
# fail at runtime (TypeError: unexpected keyword argument 'registry') on
# a machine that happens to resolve to one of those older releases (a
# pinned enterprise mirror, a shared virtualenv, a lockfile elsewhere in
# the same environment, etc).
jsonschema[format-nongpl]>=4.18,<5
# referencing is already a hard (non-extra) transitive dependency of
# jsonschema>=4.18 (Requires-Dist: referencing>=0.28.4, confirmed against
# jsonschema 4.18.0's own package metadata), so `pip install` of the line
# above always brings in a compatible referencing on its own. It is listed
# here explicitly anyway, per round-10 review feedback, so that
# validate_semantics.py's direct `from referencing import Registry,
# Resource` and `from referencing.jsonschema import DRAFT4` imports are
# backed by a declared project dependency rather than relying silently on
# another package's transitive requirement -- if jsonschema ever drops or
# relaxes that transitive pin, this line still guarantees a working
# referencing is installed. 0.28.4 is confirmed (by inspecting that
# release's own referencing/jsonschema.py) to already provide DRAFT4 and
# the Registry/Resource/.resolver() surface this script uses.
referencing>=0.28.4
openapi-spec-validator>=0.7

## 2. Why `SELLERS_USANCE`, not `SIGHT`

Per Decision 2's own action item 4 note: changing to `SIGHT` would collapse both cases into the same
scenario `export-case-1`/`export-case-6` already cover, losing the B4 `ACCEPT`/Acceptance-compound path
these two cases exist to exercise. `src/app/transaction-builder/balance-component.model.ts`'s own
`EXPORT_TENOR_OPTIONS` (line 261-264) confirms this is exactly what the real UI already does — Export's
own "Usance" picker option sends `SELLERS_USANCE` on the wire (labelled plain "Usance" per that file's own
comment: "Buyer's vs Seller's Usance is an Import-side domestic financing-structure distinction the
confirming bank has no visibility into"). The two `businessCases.js` cases previously diverged from what
the UI can actually produce — `SELLERS_USANCE` is the correction that brings the test data back in line
with real UI behavior, not a new design decision.

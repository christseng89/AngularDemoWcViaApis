# 或有负债分类账（Dr/Cr 借贷参照）测试场景

从本主题范围的测试文件中提取了6个测试场景。这些场景所证明的规则详见 Contingent Liability Ledger (Dr/Cr Reference) 与 [[Business-Rule-Index]]。

| 场景 | 前置条件（Given） | 触发操作（When） | 预期结果（Then） | 来源 |
|---|---|---|---|---|
| Import LC Sight Honour ——Utilize 后 Release 的组合操作恰好将 Folio 1 冲销一次 | 一份 ACTIVE 状态、Sight tenor 的 IPLC_LC，已有一笔 RELEASED 的 ISSUE（Folio 1 的或有负债科目对已建立）。 | A3 Document Arrival 创建一笔 PENDING 状态的 UTILIZE（不产生 GL 影响），随后 A4 的 Checker Release 完成最终释放。 | 恰好在 A4 Release 时过账一笔 Folio-1 冲销分录——Dr Documentary Credits Outstanding — Sight / Cr Customers' Liability under DC — Sight；A3 这一步骤本身不产生任何分录。——*余额影响：* LC Confirmed Balance 仅在 A4 Release 时因 Utilize 金额而减少，A3 提交时不受影响。*容差/汇率：* 不适用——Honour 不影响 ceilingAmount；容差仅适用于 Issue/Amend。 | `analysis/contingent-liability-ledger.html Folio 1 memo row + release/Honour row, Notes item 3` |
| Import LC Seller's Usance Honour + Acceptance 创建——一次 Checker Release 同时过账到两个 Folio | 一份 ACTIVE 状态、Seller's Usance tenor 的 IPLC_LC，已有一笔来自 A3 Document Arrival 的 PENDING 状态 UTILIZE。 | 执行 A6 的 Checker Release。 | 这一次 Release 会同时过账一笔 Folio-1 冲销分录（Dr Documentary Credits Outstanding — Seller's Usance / Cr Customers' Liability under DC — Seller's Usance）以及一笔 Folio-3 建立分录（Dr Acceptances & DPU — Customers' Liability (memo) / Cr Acceptances & DPU — Outstanding (memo)）。——*余额影响：* LC Confirmed Balance 减少；同时新建一份 IPLC_ACCEPTANCE 合约，拥有其自身的备忘（shadow-memo）余额，exposureNature=ACTUAL。*容差/汇率：* 本事件不适用；底层 LC 自身的 ceilingAmount 不受 Honour 影响。 | `analysis/contingent-liability-ledger.html Folio 1 release/Honour row footnote 6, Folio 3 Seller's Usance rows, Notes item 6` |
| SG Issue 后进行 Full/Partial Redemption——Folio 2 的建立/释放，与 tenor 无关 | 一份 ACTIVE 状态的父级 LC（任意 tenor），已通过 A8 开立了一份 SG。 | A9 对该 SG 进行赎回，依据 MIN(Bill Amount, SG Outstanding) 推导出 FULL_REDEEM 或 PARTIAL_REDEEM。 | A8 过账 Dr Customers' Liability under Shipping Guarantees / Cr Shipping Guarantees Outstanding（建立分录）；A9 的赎回则仅就已赎回金额过账完全相反的分录（释放分录）。——*余额影响：* SG Outstanding 余额按赎回金额减少；父级 LC 的表外风险敞口净额一旦 RELEASED，也会相应地减少。*容差/汇率：* 不适用——依据 CLAUDE.md 的决策记录，SG 不具有 tolerancePct/ceilingAmount 的概念（容差仅适用于 LC/Confirmation）。 | `analysis/contingent-liability-ledger.html Folio 2 establish and release rows, Notes item 7` |
| A3S 带 SG 的组合型 Document Arrival——在 Submit 时 LC 分支仅为备忘性质，Checker Release 时 SG 分支释放 Folio 2 | 一份 ACTIVE 状态、Sight 或 Usance tenor 的 IPLC_LC，针对其已开立一份有效的 SG。 | A3S 由 Maker 提交一笔组合型 Document Arrival，同时引用 LC（PENDING 状态的 UTILIZE）与 SG（关联的赎回分支），随后 Checker 予以释放。 | 在 Submit 时，两条分支均不产生任何或有负债的 GL 影响（均为 PENDING）。在 Checker Release 时，SG 分支自身通过 MIN() 推导出的赎回会过账一笔 Folio-2 释放分录；LC 分支自身的释放（经由 A4 或下游的 A6）依据 Coverage 表自身的描述，属于另一次独立的组合完成动作。——*余额影响：* SG Outstanding 按 MIN(Bill Amount, SG Available Balance) 减少；LC 自身的 Confirmed Balance 在其自身的 Utilize 被单独释放之前不受影响。*容差/汇率：* 本身不适用，但 LC 自身的 tightAvailableBalance 对这一匹配同一 businessEventId 的 SG 分支的抵销方式，与一笔无关的独立 SG 赎回不同（详见 CLAUDE.md 决策记录——不在本账本文档的范畴内）。 | `analysis/contingent-liability-ledger.html #coverage A3S row, Folio 2 release row footnote 8, Notes item 8` |
| Export Confirm LC 经 Present Docs 到 Honour/Accept——Folio 4 先建立后释放，中间经过一个备忘步骤 | 一份通过 B1 ISSUE（Sight 或 Usance）建立的 ACTIVE 状态 EPLC_CONFIRMATION。 | B3 创建一笔 PENDING 状态的 EPLC_EXAMINATION CREATE（Present Docs，不产生 GL 影响），随后 B4 以 HONOUR（Sight）或 ACCEPT（Usance）方式将其释放。 | B1 过账 Folio-4 建立分录；B3 不产生任何分录；B4 过账 Folio-4 释放分录（Dr Confirmation Undertakings Outstanding — [Tenor] / Cr Issuing Bank Confirmation Exposure — [Tenor]）。——*余额影响：* Confirmation 的 Confirmed Balance 仅在 B4 Release 时减少，与进口侧 A3→A4/A6 的模式一致。*容差/汇率：* Confirmation 自身的 ceilingAmount（在 B1 ISSUE/B2 AMEND 时经过容差换算）不受 B3/B4 影响——Honour/Accept 是针对已换算完成的 ceiling 进行操作。 | `analysis/contingent-liability-ledger.html Folio 4 memo row and release/Honour row, Notes item 2` |
| Export Usance Accept 后进行 B5 Settlement——Folio 4+5 组合建立，Folio 5 释放不受结算方式影响 | 一份 ACTIVE 状态、Usance tenor 的 EPLC_CONFIRMATION，已有一笔 PENDING 状态的 B3 EPLC_EXAMINATION CREATE。 | B4 的 Checker Release 触发 ACCEPT（Usance 分支），随后进行 B5 的 FULL_SETTLE 或 PARTIAL_SETTLE（无论是持有至到期还是贴现，任一模式）。 | B4 的 ACCEPT 会在同一次 Release 中同时过账 Folio-4 释放分录与 Folio-5 建立分录（Dr Confirmed Acceptances & DPU — Customers' Liability (memo) / Cr ...Outstanding (memo)）；无论结算是持有至到期还是提前贴现，B5 随后都会过账完全相反的 Folio-5 分录。——*余额影响：* Confirmation 的 Confirmed Balance 在 B4 时减少；同时新建一份与 EPLC_ACCEPTANCE 等效的备忘余额，并在 B5 时全部或部分释放。*容差/汇率：* Acceptance 备忘分支自身不适用——exposureNature=ACTUAL，不涉及容差。 | `analysis/contingent-liability-ledger.html Folio 4 release/Honour row footnote 12, Folio 5 rows, Notes items 12,13` |
